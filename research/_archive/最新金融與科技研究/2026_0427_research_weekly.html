#2 後篩選組合選擇 — 優先序 #1

Post-Screening Portfolio Selection
arXiv:2604.17593 · 2026-04-21 · q-fin.PM
◉ 極高可行 工期 2–3 天

論文要旨。當你先用篩選器（價值因子排序、流動性門檻、ESG 過濾⋯）縮小股票池後，再做組合最佳化，標準的 mean-variance 估計會帶有顯著的「選擇偏誤」，導致樣本外績效高估。論文提出修正方法（post-selection inference），把篩選步驟對統計分布的扭曲明確補回去。

為何優先 #1

  • 我方所有因子流程都是「先篩、再排、再選」三段式 — 正中論文打點
  • 過去回測夏普可能高估 0.2–0.4，修正後可分辨真假 alpha
  • 純程式碼修正，無新資料需求，2-3 天可上線

實作摘要

# src/tw-stock-scanner/portfolio/post_screening_inference.py from scipy.stats import truncnorm def post_selection_mean(returns, screen_mask, threshold): selected = returns[:, screen_mask] mu_naive = selected.mean(axis=0) sigma = selected.std(axis=0) a = (threshold - mu_naive) / sigma correction = sigma * truncnorm.mean(a, np.inf) return mu_naive - correction # 修正後的條件期望

預期效益

樣本外 Sharpe 估計更貼近實際（下修 0.1–0.3 是好事）
Drawdown 預估更保守、避免上線後爆雷
為「真假 alpha」提供統計基礎

實作風險

修正過頭使估計過於保守 → 用 cross-validation 校準
篩選函數非線性 → Linear approximation 或 bootstrap

#6 訂單簿微結構制度偵測 — 優先序 #5

arXiv:2604.20949 · 2026-04-24 · q-fin.TR
◉ 高可行 工期 5–7 天

#8 LLM 財報舞弊偵測 — 優先序 #6

◉ 高可行 工期 5–6 天

論文要旨。LLM（GPT-4o / Claude）在識別財務舞弊文本（含蓄式語意操弄、敘事偏離數字、抗壓性低的揭露）上顯著優於人類分析師，且對「老闆要求說好話」式的壓力誘導抵抗力強。

#4 多代理 LLM 推薦 — 排程實作（W4）

Signal or Noise in Multi-Agent LLM-based Stock Recommendations
arXiv:2604.17327 · 2026-04-21 · q-fin.PM
◉ 中可行 工期 7–10 天

論文要旨。讓多個 LLM agents（不同 prompt、不同 role：分析師/技術派/價值派/風險官）對同一檔股票做推薦，問：「集合多 agents 的推薦能否比單一 LLM 強？」答案：多代理一致性高的推薦才有 alpha，分歧的推薦純雜訊。

5 個 Agent 角色

角色聚焦輸入
fundamentalist三表、ROE、估值財報結構化資料
technician價量、KD、籌碼tw-stock-scanner 量價
macro_strategist產業景氣、利率總經 + ETF 流量
risk_officer下檔風險、體質負債比、Z-score
contrarian逆向、錯定價情緒 + 共識指標

PoC 範圍與成本

初期僅做台股 50 檔（市值最大 50），每月 1 號跑一次，2025-01 至 2026-04 共 16 個月，成本約 USD 50/月。

驗證假設

低分歧度（disagreement < 0.5）的全 BUY 共識，下個月超額報酬顯著為正；高分歧度的推薦無法區分 alpha。

上線/不上線決策點

  • 通過驗證 → 擴大到 1500 檔（成本約 USD 800/月）
  • 失敗 → 改僅做極端共識（全 5 agent BUY 才買）篩選層

預期效益

多視角降低單一 LLM 偏誤
分歧度本身可作為「不確定性」指標
擴展性高，可加更多 agent

實作風險

LLM 幻覺 → 強制 RAG 結構化輸入
同 base model 結論相似 → GPT + Claude + Gemini
成本失控 → 嚴控 PoC 規模
