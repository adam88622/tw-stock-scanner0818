## 1. 大盤融資維持率（maint_wavg）

### 1.1 業界公開算法

實務上（券商、財經資料商、法人風控）以公開資料估算「大盤融資維持率」的標準公式為
**融資部位總市值 ÷ 融資債務餘額**：

```
大盤融資維持率
  = Σ(個股融資餘額張數ᵢ × 收盤價ᵢ × 1000) / (上市融資金額 + 上櫃融資金額) × 100%
```

* 分子 = 全市場融資買進部位的「現值（市值）」。`× 1000` 是「張 → 股」（1 張 = 1000 股）。
* 分母 = 全市場「融資金額（貸出的錢，仟元）」，即 TWSE + TPEx 官方「融資金額餘額」合計。
* 直覺：抵押品現值 ÷ 借款，比率越低代表越接近追繳（維持率 130% 為法定追繳線）。

**判讀區間**（各家財經網站一致）：歷史中位數約 **167%**；1.6–1.7 為中性、>1.8 過熱、
<1.4 有斷頭賣壓。本代理 2026-07-09 實測 **169.4%**，2026-07-14 實測 **166.8%**，落在中性區、
與快照 `maint_wavg`（162.0%）同數量級。

## 2. 低維持率曝險廣度（maint_low140_share / maint_low130_share）

### 2.1 問題：公開資料沒有「個股融資金額」

大盤維持率的分母用「市場合計融資金額」即可，但「維持率 <140% 的個股其融資金額佔比」
需要 **個股層級的融資金額與維持率**。TWSE / TPEx 公開資料只揭露個股融資餘額**張數**，
**不揭露個股融資金額**（那是各券商實際貸出金額，屬非公開）。因此必須以成本基準代理。

### 2.2 採用的代理法

以「近 N 日均價」代理在外融資部位的平均進場成本，套用融資成數還原個股融資金額與維持率：

```
個股融資金額ᵢ（代理）= 融資餘額張ᵢ × 成本均價ᵢ × 1000 × 融資成數
個股融資維持率ᵢ      = (收盤價ᵢ × 張ᵢ × 1000) / 個股融資金額ᵢ
                     = 收盤價ᵢ / (成本均價ᵢ × 融資成數)

maint_low140_share = Σ(維持率ᵢ < 1.40 之融資金額ᵢ) / Σ(融資金額ᵢ) × 100%
maint_low130_share = Σ(維持率ᵢ < 1.30 之融資金額ᵢ) / Σ(融資金額ᵢ) × 100%
```

參數（`scanners/deleveraging_sources.py` 常數，可調）：

* **成本均價** = 近 `60` 交易日收盤均價（`_COST_WINDOW=60`，代理典型融資持有期之平均進場價）。
* **融資成數** 上市 `60%`、上櫃 `50%`（`_MARGIN_RATE_TWSE / _MARGIN_RATE_TPEX`，現行主管機關規定）。
  * 直覺檢核：若股價 = 成本，維持率 = 1/0.6 = **166.7%**，正好落在市場中位數，佐證成數設定合理。
  * 維持率 <140% ⇔ 上市股票自成本下跌 >16%（`收盤/成本 < 0.84`）。

實測（2026-07-09）：low140 = **4.93%**、low130 = **0.78%**；快照為 7.22% / 1.66%。
同數量級。此分佈對「成本視窗」與「融資成數」敏感（屬代理近似），**絕對值僅供趨勢參考**；
維持率的絕對水位以第 1 節之直接公式（`maint_wavg`）為準。

## 3. 大盤融資融券（fetch_margin_market）

| 欄位 | 定義（對齊快照口徑）| 實測 2026-07-09 | 快照 latest |
|---|---|---|---|
| `margin_total` | 融資餘額**市值**（兆元）= Σ(TWSE+TPEx 融資張 × 收盤價 × 1000)/1e12 | 1.409 | 1.576 |
| `margin_util` | 融資使用率（%）= TWSE 個股使用率之融資餘額加權平均 = Σ(餘額張²/限額張)/Σ(餘額張) | 17.169 | 17.120 |
| `short_balance` | 融券餘額（萬張）= (TWSE+TPEx 融券今日餘額張)/1e4 | 24.063 | 24.700 |
| `short_margin_ratio` | 券資比（%）= 融券張 / 融資張 × 100 | 1.994 | 2.013 |

### 3.1 為何 margin_total 是「市值」而非「餘額金額/張數」

快照 `margin_total` 有三個特徵，只有「融資部位市值」同時滿足：

1. **數量級 ~1.5**：融資餘額金額合計僅 0.83 兆、張數 1.21 千萬張，皆非 1.5；
   融資市值 Σ(張×價×1000) 才是 ~1.5 兆量級。
2. **逐日大幅波動**（0706→0709：1.670→1.571→1.540→1.576，單日達 ±6%）：
   融資餘額（金額/張數）逐日僅 ±1% 內，不可能 ±6%；只有隨股價變動的「市值」才會。
3. **百分位近歷史高（pctl 98.72）**：融資張數處歷史高位，乘上接近前高的指數 →
   融資市值創新高，與 pctl 一致。

因此 `margin_total` 對齊快照的是 **融資餘額市值（兆元）**，恰為第 1 節維持率公式的分子。

> **覆蓋率注意**：市值計算需個股收盤價，受 `daily_prices` 當日覆蓋率影響。
> 2026-07-09 DB 當日價格覆蓋不全（融資張覆蓋約 71%/86%），故實測 1.409 較快照 1.576 偏低約 11%。
> 在價格資料完整之交易日偏差更小。若管線要求嚴格連續（避免 append 時百分位跳動），
> 可選擇性以覆蓋修正：`margin_total ≈ maint_wavg/100 × 官方融資金額(兆)`
> （用官方完整融資金額還原完整市值），或以歷史 `快照值/公開值` 比例做校正常數。

### 3.2 為何 margin_util 用 TWSE 加權平均個股使用率

單純「大盤融資餘額 ÷ 融資限額」約 3.9%（限額為法定上限，過大），與快照 17.12% 差 5 倍。
改用「個股融資使用率（餘額/限額）以融資餘額加權平均」= Σ(bal²/limit)/Σ(bal)，
TWSE 實測 **17.17%**，與快照 **17.12%** 吻合（僅 TWSE，含上櫃則 19.1% 偏高）。
資料來源同 `MI_MARGN?selectType=ALL` `tables[1]`（第 6 欄餘額、第 7 欄「次一營業日限額」）。

## 4. 加權指數 OHLC（fetch_taiex_daily）

* 來源：TWSE `indicesReport/MI_5MINS_HIST?response=json&date=YYYYMMDD`
  （回傳當月每日「發行量加權股價指數」開/最高/最低/收盤；程式以 ROC 日期篩當日列）。
* 回 `{close, high, low}`。實測 2026-07-09：close **45354.61** / high 46064.06 / low 45352.41，
  **與快照 `taiex_close`（45354.609375）逐位元一致**。
* 非交易日（如 2026-07-11 週六）該日無列 → 回 None。
* 註：`FMTQIK` 亦有指數收盤但**無盤中高低**，故採 `MI_5MINS_HIST`（含 OHLC，可算回撤 taiex_dd）。

## 5. 當沖成交值佔比（fetch_daytrade）

* 來源：TWSE `exchangeReport/TWTB4U?response=json&date=YYYYMMDD` → `tables[0]`
  （當日沖銷交易統計資訊，大盤合計單列）。
* 定義：取「當日沖銷總**買進**成交金額占市場比重%」與「總**賣出**成交金額占市場比重%」之平均。
* 實測 2026-07-09：(42.33 + 42.42)/2 = **42.375**，**與快照 `daytrade_ratio` 完全一致**。
  2026-07-14：38.92。
* 尚未公布 / 假日 → 回 None（此項原本就允許 pending）。

## 7. 抓取穩健性

* 全部 `requests.get` 帶 `timeout=25` 與 `User-Agent` header。
* 任一來源失敗 / 非交易日 / 尚未公布 → 對應函式回 `None`（絕不 crash、絕不回 0）。
* TPEx 缺資料時，`fetch_margin_market` / `fetch_maint_proxy` 自動降級為僅 TWSE（回值仍非 None）。
* DB 一律唯讀 `file:db/scanner.db?mode=ro&immutable=1`（`uri=True`），不觸碰 3GB+WAL。
